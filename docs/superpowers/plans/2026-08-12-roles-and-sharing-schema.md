# Roles and Resource Sharing Schema Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the roles, resource-ownership, sharing, and soft-delete schema defined in `docs/superpowers/specs/2026-08-12-roles-and-sharing-design.md`.

**Architecture:** SQLAlchemy 2.0 declarative models under `api/app/models/`, one hand-written Alembic migration per task under `api/alembic/versions/`, and two thin service modules under `api/app/services/` (`resources.py` for transactional creation of `resources` + type-table rows, `authorization.py` for the visibility rule, `organizations.py` for personal-org signup). No HTTP endpoints are added in this plan — auth/API surface is a separate future plan.

**Tech Stack:** FastAPI, SQLAlchemy 2.0 (`Mapped`/`mapped_column`), Alembic, PostgreSQL 15 + PostGIS, GeoAlchemy2, pytest (via the existing `db_session`/`client` fixtures in `api/tests/conftest.py`).

## Global Constraints

- Test DB schema comes from `Base.metadata.create_all()` in `api/tests/conftest.py`, NOT from Alembic — every constraint (enum, check, unique, index) MUST live on the model's `__table_args__`/column definition, not only in the migration, or tests won't exercise it.
- Every new/changed table needs both: (a) the SQLAlchemy model change, (b) a hand-written Alembic migration mirroring it exactly — follow the existing style in `api/alembic/versions/c1486bd260ac_create_users_table.py` and `3d7a1ec7bfa6_create_organizations_table.py`.
- Enum columns use `sqlalchemy.Enum(PyEnum, name=..., values_callable=lambda x: [e.value for e in x])` so Postgres stores the lowercase `.value` strings, not the Python member names.
- UUID primary/foreign keys use `sqlalchemy.dialects.postgresql.UUID(as_uuid=True)`, matching existing models.
- Run tests with: `cd api && python -m pytest tests/ -v` (requires `docker compose up -d db` running first — confirmed available in this environment).
- Run migrations with: `cd api && alembic upgrade head` (needs `DATABASE_URL` pointed at the dev db, per `.env`/`.env.example`).
- Commit after every task using the existing repo convention (`type: short description`, seen in `git log`).

# api/app/services/authorization.py
from sqlalchemy import and_, or_
from sqlalchemy.orm import Session

from app.models.enums import Role, ShareScope
from app.models.resource import Resource
from app.models.resource_share import ResourceShare
from app.models.user import User


def can_view_resource(db: Session, user: User, resource: Resource) -> bool:
    if resource.deleted_at is not None:
        return False
    if resource.org_id != user.org_id:
        return False
    if resource.owner_id == user.id:
        return True
    if user.role in (Role.OWNER, Role.ADMIN):
        return True

    share_exists = (
        db.query(ResourceShare)
        .filter(
            ResourceShare.resource_id == resource.id,
            or_(
                ResourceShare.scope == ShareScope.ORGANIZATION,
                and_(
                    ResourceShare.scope == ShareScope.USER,
                    ResourceShare.shared_with_user_id == user.id,
                ),
            ),
        )
        .first()
    )
    return share_exists is not None
